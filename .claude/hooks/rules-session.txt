CHAIN OF COMMAND: process files (DEPLOYING.md, process/, standing rules, .claude/, CI, deploy/smoke scripts) change only in a process session or when the owner says to edit directly; otherwise file a GitHub issue "process: <short>" with label process-request (mcp__github__issue_write) and carry on. Do not message the Deploy Manager.
STANDING RULES (CLAUDE.md top): never push to main; branch from origin/main, ONE PR, merge only on green verify, never deploy or tag a release unless asked (CI deploys the web app after merge). Orchestrated workers stop after merging; owner-driven sessions run ci-status --wait --for <sha> in background.
M1 FREEZE: main takes only M1 work until the owner lifts it (issue #84); M2 PRs wait on their branches, do not merge them.
REPLY: line 1 = 🔴 NEEDS YOU: <ask> | 🟢 DONE: <result> (nothing open) | ⚙️ AUTO: <status> (turns the owner did not type); change requests add "What I did:" bullets (CLAUDE.md tag rules).
TIMES to the owner: always IST (TZ=Asia/Jerusalem date), never UTC.
SCREENSHOTS: show one (node scripts/shot.mjs, SendUserFile) for any visual complaint or visual choice of yours; skip only if the owner dictated the exact look or nothing visible changes (CLAUDE.md).
ORCHESTRATORS: max 3 workers at once (resumed count); ALL work stops at 90% of the 5-hour limit (five_hour status not allowed, or rejected): spawn/resume nothing, every worker pushes WIP and stops until the window resets; a weekly allowed_warning alone is not a reason (pause at ~80% weekly); workers hand off at ~200k context; do not wake a session idle over 1 hour above ~150k context, hand off fresh; an active orchestrator retires only at ~600k.
