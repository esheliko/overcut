# 0003 GPU: wgpu, WebGPU first, WebGL2 fallback, linear light
**Status**: proposed (spike S2 results below: native parity proven, browser run pending)

**Context.** Real-time multi-layer compositing and effects need the GPU everywhere; browsers expose WebGPU (not yet everywhere) and WebGL2.

**Decision.** The compositor is written on **wgpu**, targeting WebGPU in browsers and Vulkan/Metal/DX12 natively, with wgpu's WebGL2 (GLES) backend as the web fallback. Effects are WGSL (a GLSL ES variant generated for GLES where needed). Compositing is in **linear light** with an explicit input/output transform (sRGB/Rec.709 first); the design leaves room for wide-gamut/HDR (PV-07) so it never needs a rewrite.

**Consequences.** (+) one shader language and renderer; (-) the WebGL2 path has feature limits (storage buffers, compute) so some effects ship a degraded path; golden-frame tests run per backend with tolerance. If S2 fails, ship WebGPU-only plus a reduced Canvas2D/WebGL2 renderer in degraded mode.

## S2 results (M1-020, 2026-11-22)
**What was built**: `crates/render` (`app-render`): `Compositor::render(w, h, layers)` blends N layers (2D transform: centre, scale, rotation; opacity) in linear light into an `Rgba16Float` accumulation target (layer textures are `Rgba8UnormSrgb`, so sampling decodes sRGB), then a present pass encodes sRGB in the shader (explicit maths, not hardware sRGB targets) into `Rgba8Unorm`. `render_to_rgba8` is the native blocking readback. Golden harness: `crates/render/tests/golden.rs` (PNG golden `tests/golden/three_layers.png`, per-channel tolerance 3/255, `UPDATE_GOLDENS=1` regenerates). Same WGSL on every backend.

**Proved** (container, software rasteriser llvmpipe 20.1.2 via lavapipe/Vulkan and via the GL (GLES) backend):
- Identical output across Vulkan and the GL (WebGL2-equivalent) backend for the 3-layer scene: max per-channel diff **1/255** between backends, 0 and 1 against the golden.
- Opacity 0 leaves black; an opaque layer round-trips sRGB within 1 code value.
- `cargo check -p app-render --target wasm32-unknown-unknown` passes with `webgpu` + `webgl` backends (both enabled on wasm, runtime chooses).

**Not proved (needs a browser / reference hardware)**:
- Real WebGPU and real WebGL2 in a browser (the native GL backend is the same GLES code path wgpu uses for WebGL2, but not the browser's ANGLE/driver stack). Needs a Playwright/Chromium WebGPU run and one on a phone.
- 60 fps for 3 layers at 1080p on the reference laptop: not measured (software rasteriser numbers are meaningless). Needs ADR 0013 reference devices.
- Float render targets on WebGL2 need `EXT_color_buffer_half_float`/`float`; present on virtually all devices, but the fallback when absent (8-bit accumulation, slightly more banding) is not built.

**Known spike shortcuts** (to fix in M1-021, not blockers): layer textures, uniform buffers and bind groups are created per frame; browser readback (`map_async`) is not wired; one pipeline, no effects.

**Recommendation**: ADR stays on wgpu; keep WGSL-only, no storage buffers/compute in the base path. Proceed to M1-021. CI must install a software adapter (`mesa-vulkan-drivers`) or the golden test only skips; tracked as a process request.
