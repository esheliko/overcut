# 0003 GPU: wgpu, WebGPU first, WebGL2 fallback, linear light
**Status**: accepted for the browser path as built in M1-023 (one wgpu compositor in wasm, WebGL2 verified end to end in headless Chromium; WebGPU implemented, not verified on hardware). Reference-device frame times (ADR 0013) still pending.

**Context.** Real-time multi-layer compositing and effects need the GPU everywhere; browsers expose WebGPU (not yet everywhere) and WebGL2.

**Decision.** The compositor is written on **wgpu**, targeting WebGPU in browsers and Vulkan/Metal/DX12 natively, with wgpu's WebGL2 (GLES) backend as the web fallback. Effects are WGSL (a GLSL ES variant generated for GLES where needed). Compositing is in **linear light** with an explicit input/output transform (sRGB/Rec.709 first); the design leaves room for wide-gamut/HDR (PV-07) so it never needs a rewrite.

**Consequences.** (+) one shader language and renderer; (-) the WebGL2 path has feature limits (storage buffers, compute) so some effects ship a degraded path; golden-frame tests run per backend with tolerance. If S2 fails, ship WebGPU-only plus a reduced Canvas2D/WebGL2 renderer in degraded mode.

## S2 results (M1-020, 2026-11-22)
**What was built**: `crates/render` (`app-render`): `Compositor::render(w, h, layers)` blends N layers (2D transform: centre, scale, rotation; opacity) in linear light into an `Rgba16Float` accumulation target (layer textures are `Rgba8UnormSrgb`, so sampling decodes sRGB), then a present pass encodes sRGB in the shader (explicit maths, not hardware sRGB targets) into `Rgba8Unorm`. `render_to_rgba8` is the native blocking readback. Golden harness: `crates/render/tests/golden.rs` (PNG golden `tests/golden/three_layers.png`, per-channel tolerance 3/255, `UPDATE_GOLDENS=1` regenerates). Same WGSL on every backend.

**Proved** (container, software rasteriser llvmpipe 20.1.2 via lavapipe/Vulkan and via the GL (GLES) backend):
- Identical output across Vulkan and the GL (WebGL2-equivalent) backend for the 3-layer scene: max per-channel diff **1/255** between backends, 0 and 1 against the golden.
- Opacity 0 leaves black; an opaque layer round-trips sRGB within 1 code value.
- `cargo check -p app-render --target wasm32-unknown-unknown` passes with `webgpu` + `webgl` backends (both enabled on wasm, runtime chooses).

**Not proved (needs a browser / reference hardware)**:
- Real WebGPU and real WebGL2 in a browser (the native GL backend is the same GLES code path wgpu uses for WebGL2, but not the browser's ANGLE/driver stack). Needs a Playwright/Chromium WebGPU run and one on a phone.
- 60 fps for 3 layers at 1080p on the reference laptop: not measured (software rasteriser numbers are meaningless). Needs ADR 0013 reference devices.
- Float render targets on WebGL2 need `EXT_color_buffer_half_float`/`float`; present on virtually all devices. The fallback is built in M1-021 (below) but only exercised on native GL here, not in a browser.

**Spike shortcuts** listed here were fixed in M1-021 (next section).

**Recommendation**: ADR stays on wgpu; keep WGSL-only, no storage buffers/compute in the base path. Proceed to M1-021. CI must install a software adapter (`mesa-vulkan-drivers`) or the golden test only skips; tracked as a process request.

## M1-021 results (colour pipeline v0 and hot path, 2026-11-22)
- **Colour**: image layers are sRGB, decoded by the texture format; video layers are planar 4:2:0 YCbCr decoded in the shader with BT.709 (BT.601 also supported) and limited or full range taken from the frame metadata, then treated as sRGB-encoded (v0 assumption; BT.1886/gamut/HDR are later). Blending is linear premultiplied; output is encoded to sRGB in the shader. Pure maths and CPU reference in `crates/render/src/colour.rs`. Goldens: `three_layers.png`, `colour_chart.png` (8 colour bars, 16-step grey ramp, alpha ramp and hard alpha edge, soft disc) plus analytic tests (50% white over black = 188, grey steps exact, YUV bars for both ranges and matrices).
- **Hot path**: layer textures, bind groups (one per layer slot), one uniform buffer with per-layer dynamic offsets, the accumulation/output targets and the readback buffer are persistent. `Compositor::alloc_stats()` counts every texture/buffer/bind group created; a test asserts it does not move across 20 frames of 1080p x 3 layers (2 RGBA + 1 YUV) and across repeated readbacks, and that a layer-count or size change rebuilds only the affected slot. Not counted: wgpu's internal staging for `write_texture`/`write_buffer` (a pooled upload path; upload cost is per frame by nature).
- **Frame time, 1080p, 3 layers, llvmpipe (software, NOT representative)**: about 43 ms debug / 50 ms release per frame including 24 MB of layer uploads and a GPU wait, on both Vulkan (lavapipe) and GL. This is a CPU rasteriser, so it says nothing about the 60 fps budget; reference-device numbers still needed (ADR 0013).
- **Browser readback**: `read_rgba8_into` is async (`map_async` + waker); native completes on first poll, web resolves from the event loop. It reuses the caller's `Vec`. One readback in flight at a time; a pipelined export ring (2-3 buffers) is for M1-022 if profiling asks. `cargo check --target wasm32-unknown-unknown` passes; not run in a browser yet.
- **WebGL2 fallback**: `AccumFormat::for_adapter` checks that `Rgba16Float` is renderable and blendable; otherwise accumulation uses `Rgba8UnormSrgb` (hardware decodes on blend, encodes on write, so blending stays linear). Quality loss: each layer rounds to 8-bit sRGB (measured max 1/255 against the float path on both test scenes; expect up to ~0.5 code value per layer, more banding in very dark gradients) and values above 1.0 clip (matters for HDR/wide gamut later). Tolerance in tests is 3/255.
- **Test environment**: both Vulkan and GL adapters need `mesa-vulkan-drivers libgl1-mesa-dri libegl1`; without them the golden tests skip (CI install tracked as a process request).

## M1-023 results (the one browser compositor, 2026-11-23)
- **Built**: `crates/render` is bound to wasm (`crates/wasm/src/render.rs`, `GpuRenderer`) and runs in Workers on an `OffscreenCanvas`: the preview Worker (presents; also hosts the player loop, decoding and audio mixing) and the export Worker (composites offscreen, `VideoFrame` from a readback buffer or the canvas). The TS WebGL2 preview compositor and the Canvas 2D export compositor are deleted. Decoded `VideoFrame`s are imported on the GPU (`copy_external_image_to_texture`), CPU frames upload as RGBA, display rotation is part of `Layer`.
- **WebGL2 proven in a browser** (headless Chromium, ANGLE on SwiftShader): float16 accumulation chosen from the adapter, preview playback 2 s with 0 drops and 0 stalls, export of the S3 scene (flash/click aligned, byte-identical files with pinned creation time), preview and export pixels identical (max diff 0/255 against a 3/255 tolerance) for a rotated phone clip and the flash clip, no GPU object created per frame while scrubbing. Needed fixes found on the way: WebGL2 completes `map_async` only when the device is polled again (the readback now yields to the event loop between polls); the `Instance` must outlive the renderer.
- **WebGPU not proven**: in this environment (SwiftShader with `--enable-unsafe-webgpu`) the adapter, device, CPU-layer rendering and readback work, but importing a `VideoFrame` and then mapping the readback buffer fails (Dawn: "A valid external Instance reference no longer exists"), as does readback after presenting on the same renderer. So `auto` picks WebGPU only when a self-test (VideoFrame import + readback on a scratch canvas) passes, else WebGL2. Needs a run on real WebGPU hardware before WebGPU is the default there in earnest.
- **Costs**: `app_wasm_bg.wasm` 881 KB -> 3.40 MB (gzip 329 KB -> 1.19 MB, no `wasm-opt` here); split: the UI thread loads the 881 KB build without the GPU code (`wasm-pkg`), the Workers that composite load the full 3.40 MB one (`wasm-pkg/gpu`, cargo feature `render`); cold load on Fast 3G is back to the UI wasm of before #44 (details in `docs/features/render.md`). Frame times in `docs/features/render.md`, `preview.md`, `export.md` are software-rasteriser numbers, not budgets.
