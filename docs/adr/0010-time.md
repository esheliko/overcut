# 0010 Time as integer ticks
**Status**: proposed

**Decision.** All times and durations are `i64` **ticks** at 705,600,000 per second (chosen because it divides exactly into one frame of 24, 25, 30, 48, 50, 60 and 120 fps, of the NTSC rates 24000/1001, 30000/1001 and 60000/1001 fps, and into one sample of 44.1, 48, 88.2, 96 and 192 kHz audio). Frame and sample indices are derived with explicit, documented rounding (frame containing the time = floor; export frame times are exact multiples of the project frame duration as a `Rational`). Floats are never used for timeline positions. Property tests cover round-trips and monotonicity.

**Consequences.** (+) no drift, exact A/V sync, deterministic export, stable serialization (ticks as integers in JSON; large values as strings only if a JS 2^53 limit is reached: 2^53 ticks is about 145 years, safe). (-) conversions to browser APIs (microseconds for WebCodecs, seconds for media elements) are done at the boundary only, in one module.
