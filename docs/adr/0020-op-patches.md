# 0020 Edits report what they changed (op patches)
**Status**: proposed (engineering; implemented additively, no ABI bump)

**Context.** After every edit the UI called `Engine.editing.project()` (the whole project as JSON), `JSON.parse`d it on the UI thread, rebuilt its scene from it, and re-stringified the whole project for the preview worker. Split on `/?sample=2h` (2300 clips) took 42 ms at 1x and 180 ms at 4x CPU throttle against the budget of <= 8 ms apply + patch at 5k clips (`docs/PERFORMANCE.md`). ADR 0006 already says "applying an op returns ... a patch for the UI"; until now only `changed` and the undo flags came back.

**Decision.**
- `EditOutcome` gains an optional `patch` (`crates/timeline/src/patch.rs`). The editor keeps a shadow copy of the project as the UI last saw it and, after every apply/undo/redo, diffs the project against it. The diff is generic, so every current and future op gets a patch with no per-op code and no way to forget one.
- A patch holds: the changed sequences; per sequence its shell (everything but the tracks) when it changed, the full track order when a track was added/removed/moved, and per changed track its shell and ONE splice of the clip list (common prefix and suffix kept; `start`, `remove`, `insert`); the media list when it changed.
- No patch (field absent while `changed` is true) means "re-read the project": the project id/name/schema or the list of sequences changed. The shadow is re-based, so the next edit has a patch again. A recovered session re-bases the shadow too.
- It is additive and optional on the wire (an old UI ignores it, a new UI falls back to `project()` without it), so `ABI_VERSION` / `EXPECTED_ABI` stay at 4. wasm and Tauri forward the outcome string unchanged, so both platforms carry it with no binding change.
- The UI applies the patch immutably (`applyEditPatch`, `packages/engine-client/src/patch.ts`): every unchanged track and clip keeps its object identity, so React, the timeline canvas and the preview can skip them. The Rust `apply_patch` is the reference; `packages/engine-client/schema/patch-contract.json` (generated by a Rust test from real edits) pins the TypeScript implementation to it.

**Consequences.** (+) edit cost no longer scales with the project size on the UI thread: a split sends one clip removed and two inserted. (+) The preview worker can be sent the same patch. (-) The engine holds one more copy of the project (the shadow; 5k clips is a few hundred KB). (-) A ripple edit that shifts every later clip still sends all of them (one splice, still less than the whole project). Checked by: a property test (random ops, undo and redo: patched copy == project), the contract file, and the store tests.

**Rejected.** Per-op patches (35 variants x forward/inverse: a bug per op; the diff is op-independent and tested once). Returning the inverse ops (the UI has no op interpreter and the shell changes would need one).
