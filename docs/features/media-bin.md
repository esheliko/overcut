# Feature: media bin and import (M1-032)

Code: `apps/web/src/media/` (`plan.ts` pure logic, `sources.ts` picker/drop/paste/handles, `probe.ts`, `useMediaBin.ts` state, `MediaBin.tsx` UI), wiring in `App.tsx`. Tests: `tests/unit/media-plan.test.ts`, `tests/smoke/media-bin.spec.ts`.
Serves the activation test (PRODUCT.md: import, trim, export in under 90 s for a first-time user): **zero setup questions**.

## Behaviour
- **A project exists from the first second.** When the engine is ready the app opens an empty project (one sequence, one video track `V1`, one audio track `A1`, 1920x1080, 30 fps, 48 kHz). No "new project" dialog.
- **Import** (all paths end in `useMediaBin.importSources`):
  - the big **Import media** target (empty bin) or the **Import media** button (bin has items): the system picker, multiple files, `video/*,audio/*,image/*`. On Chromium desktop (`showOpenFilePicker`, fine pointer) it returns **file handles**; elsewhere a plain `<input type=file multiple accept=...>`, which on iOS and Android offers the camera roll.
  - **Drag and drop** of files anywhere on the page (the window listens; a full-screen "Drop to import" overlay shows while files are over the page). Dropping on the timeline or preview is the same import. Folders are ignored.
  - **Paste** (`Ctrl/Cmd+V`) of files, except inside text fields.
- **The very first import into an empty project goes straight onto the timeline, at 0, and sets the sequence's frame rate and size from the first clip with a picture** (rotation applied: a phone clip with a 90 degree matrix gives 1080x1920... swapped sides; variable frame rate or no rate gives 30). Every file of that first batch is appended in order. **One import rule everywhere (UX r15):** a file always lands in the bin, and it also goes onto the timeline when the timeline is empty (no clips, even if the bin holds media) or when the person dropped it onto the timeline; every other import (Import button, paste, the phone's Media sheet) fills only the bin and shows a toast "Added to Media" with an **Add to timeline** action (`media.addedToBin`, 7 s, sits just above the timeline, never on the picture). On a phone the Media sheet closes only when the import landed on the timeline; an import that only reached the bin leaves the sheet open, so the person never closes into nothing. An audio file never changes the sequence; the first picture added afterwards does, while the project still has no picture media (`sequenceIsUnset`). If the user already chose the size and/or frame rate in the canvas settings (`docs/features/canvas.md`) the import leaves the chosen part alone (`Sequence.size_fixed` / `rate_fixed`).
- **Add to timeline**: the `+` button on a card (44 px, labelled "Add <name> to the timeline", Enter/Space from the keyboard, announced "Added to the timeline"), or **drag a card onto the timeline** (mouse/pen; touch uses `+`). Placement: at the playhead when both tracks are free there, else after the last clip. A video with sound becomes **two clips** (picture on the first video track, sound on the first audio track) from **one op array = one undo step**; audio goes on the audio track; a still is `STILL_SECONDS` (5 s) long. Ops are `insert_clip` through `Engine.editing.apply` (ADR 0006), never direct mutation.
- **Each card shows** a poster (first decoded frame, 320 px JPEG, or a stills's own image; audio gets an icon), name, length, size in pixels, codec ("H.264 + AAC"), file size. Search box filters by name.
- **Probe on import**: `Engine.media.open(file)`: the container index is read with range reads (`Blob.slice`), the bytes of the file are never loaded whole (a 64 MB file opens by reading a sliver: media-io.md). The handle is closed after the poster is drawn; preview (M1-033) opens it again. Stills go through `createImageBitmap` (the browser decodes them).
- **Errors are never silent.** A card turns red and says, in order: the file name and format, the engine's own sentence (which names the codec in words: "This device cannot decode H.265 (HEVC) video (...). Convert the file to H.264/AAC ..."), and what works everywhere. A non-media file ("notes.pdf is not a video, audio or image file, so it was skipped") and a damaged file ("could not be read") get their own messages. The message is also announced to screen readers; the card has a dismiss button.
- **Reopening**: each media's `uri` is `fs:<id>` (handle stored in IndexedDB `overcut-media`) on Chromium, else `file:<name>:<size>`. When the project opens (restored or recovered) `handleState(uri)` says per media: `granted` (the `File` comes back by itself), `prompt` or `missing`. **Needs permission (UX r15 CUST-1):** after every reload Chromium keeps the stored handle but asks the person again (permission `prompt`; Chrome 122+ offers "Allow on every visit" in that prompt). Those cards say **Needs permission to open** (not "not found"), a note says "N files need your permission to open after the reload", and ONE **Allow access** action (note, bin bar, card) calls `requestPermission` for every kept handle inside the same click (`allowAll`, all prompts started before any await, handles cached in memory), then the granted files come back ready (`useMediaBin.allowAccess`). Only truly unreadable media (no handle, or the file cannot be read) say missing and keep **Choose file** / "Choose all N missing files". A file picked through a plain `<input>` (phones, Firefox, Safari) has no handle and no browser lets a page keep one across a reload, so its card says so ("Your browser does not keep imported files after a reload. Choose it again to use it.") instead of "not found"; copying every import into OPFS to avoid this was rejected (doubles disk use for multi-GB video). **Refusals**: an unreadable file's card is two lines at most ("Can't read fake.mp4. It may be damaged or not really a MP4 file." / "Can't import x.mp3 (MP3). This format isn't supported here yet.") with a **Details** expander holding the engine's own sentence and the list of formats that always work (`media.err.*`). When the Media sheet is closed (phone) the same two lines show in a dismissible notice (`refusal-note`, 44 px close, clamps to two lines, leaves after 9 s, never over the tool strip); the live-region announcement stays. A relinked file must match the stored **fingerprint** (`fingerprintFile`, 128 KiB read), else the name; a moved file's new uri is recorded with `set_media`. Offline media keep their clips; nothing is deleted. Files restored from a handle are probed again on first use (`+`).

## Data model
`MediaRef { id, kind, name, uri, duration (null for stills), hash }`. `hash` is the `b3-64k` fingerprint computed at import (`fingerprintFile`, persistence.md).

## Accessibility and layout
Every action is a real button (picker, `+`, dismiss, relink); cards are a labelled list; state changes use the live region. Targets are at least 44 px; the bin is the Media sheet on a phone and the left panel from 720 px; the page never scrolls sideways (smoke checks it).

## Limits and decisions
- **Imports are edit ops** (`add_media`, `set_sequence_format`, `remove_media` in `app-timeline`, pinned by `edit-contract.json`), applied through the autosaving project session (`usePersistence`), so they are undoable, journaled and recovered after a crash. The first import is **one undo step** that adds the media, adopts the sequence format and inserts the clips. `remove_media` is the inverse of `add_media` and refuses media a clip still uses. If durable storage is unavailable the bare engine edits an in-memory project (the editor still works; persistence says why it is not saving). The bin applies its ops through the shared project store (`store/projectStore.ts`, M1-024) and derives its cards from the store's project whenever it changes, so an undo or redo anywhere (timeline shortcut, button) removes or restores the card; cards of removed media are kept so redo brings them back with their poster. Files the preview needs are read through the bin (`fileOf`). The empty preview offers the same import button as the empty bin. A new project is empty; `?sample` starts with the sample clips (smoke tests of timeline editing).
- Matroska (`.mkv`) is not importable yet. **MP3 and WAV (PCM 8/16/24/32-bit and 32-bit float) import since UX r15** (`demux/mp3.rs`, `demux/wav.rs`; media-io.md). WAV that is compressed (ADPCM, A-law ...), MP2/MP1 and files with more than 8 channels get a specific "convert it" message. FLAC, OGG and AIFF are still not importable.
- The playback timecode and timeline are still 30 fps (M1-033 / M1-034 use the sequence rate).
- HEIC stills depend on the browser.

## Test plan
Unit: classify, first-picture settings, op shapes, placement, labels. Smoke (desktop and phone): empty target, first import auto-add with poster/codec/resolution, `+` by keyboard, unsupported and non-media files, drop on the preview with overlay, paste, bin to timeline drag (desktop), no horizontal overflow.

## Offline media that comes back (relink)
- Media offline at first request used to stay a placeholder until reload. The bin now exposes `readyIds`; when an id turns ready (relink, restored handle permission) the timeline's `MediaLayer.refresh(id)` closes the stale decoder handle, drops the cached waveform error and redraws (waveforms and filmstrips are requested again), and the preview Worker is handed the file (`useWorkerMedia`, keyed on `readyIds`).
- When a media item leaves the project, `MediaLayer.release(id)` closes its decoder handle (`MediaHost.release`, `engineMediaHost`). Tests: `tests/unit/engine-host.test.ts`, `tests/unit/offline-media.test.ts`.

## Filter, sort, tags and 10k items (PM-03)
- **Type filter** (All / Video / Audio / Images chips), **sort** (Date added, newest first; Name, numbers in order; Length, longest first, stills last), **tag filter** (select, shown once any tag exists) and the search box (matches names and tags). Pure logic in `media/binView.ts` (`viewBin`), tested in `tests/unit/bin-view.test.ts`. Items still being read or refused stay on top whatever the filter. "N of M shown" is announced politely.
- **Tags are project data**: `MediaRef.tags` (omitted from the file when empty, so old files and hashes are unchanged) set by the edit op `set_media_tags { media, tags }` (`app-timeline`, pinned in `edit-contract.json`). Tags are trimmed, unique in any case, at most 16 of 40 characters (`BadTags` otherwise). One op per change, undoable, journaled, recovered. UI: the tag button on a card opens a dialog with chips (remove) and an add field.
- **10k items**: lists over 100 cards render only the rows in view (`Windowed` in `MediaBin.tsx`, fixed 72 px rows, scroll of the panel body, row range from `windowRange`). Measured (container, not representative): `viewBin` filter + sort over 10,000 items about 5 ms; smoke test with 10,000 media in the project: about 30-130 ms from clicking a type filter to the re-rendered window, 8 rows in the DOM (never more than 120).

## Add as overlay (M2 UX r13, #246)
A card whose media is not on the timeline yet (and is not sound) has a second action next to Tags and "+": **Add as overlay** (`bin-add-overlay`, picture-in-picture icon). It runs the same code as the timeline's More > "Add as overlay on a new track" (`addMediaItem` in `App.tsx`): a new video track on top, the clip on it at the playhead, then the new clip selected. Touch: always shown, 44 px. Mouse: revealed on hover or focus like Tags. Media already on the timeline keeps just its "+" (the card stays two lines on a phone); the overlay for it stays in More and the palette (`media.addOverlay`).

## Formats the panel advertises (UX r15)
The chips on the empty drop zone come from one list, `media/formats.ts` (`IMPORT_FORMATS`): only formats that really import (MP4, MOV, WebM, M4A, JPG, PNG). A chip is a promise: when WAV or MP3 import ships (lane C of round 15, `crates/media`), adding it there is the one-line change. The file input and picker accept all `audio/*`; a format that cannot be decoded gets the two-line card above, never a silent failure.

## Add as overlay opens a picker (UX r15 DESK-5 / PHONE-4)
"Add as overlay" (timeline toolbar, More menu, command palette, the phone strip's Overlay) never picks media for the person: it opens a **picker of the bin's pictures and videos** (thumbnail grid, `media/OverlayPicker.tsx`, sound is not offered). Choosing one puts it on a new video track above, at the playhead, and selects it. The Media card's own overlay button still adds that card directly. An empty bin says to import first.

## Card states (UX r15 DESK-15)
The accent outline on a bin card now means **the card you tapped** (selected; the one whose "+" is next), not "on the timeline"; the timeline state is the "On the timeline" pill (words in the grid, check and count in the list so names are not cut). Tapping a card selects it (a phone tap no longer does nothing).
