# Media I/O: decoder traits, frame cache (M1-011), MP4/MOV + WebM demux (M1-012)

Crate: `crates/media` (`app-media`); web backend in `packages/engine-client/src/decode`. Policy per platform: ADR 0004.

## Behaviour
- `Source`: random-access bytes (`len`, `read_at`). `Decoder`: `info()`, `video_frame(index)`, `audio(start_sample, count)`.
  Methods are std `async fn`s (no runtime dependency, WASM-safe); futures are intentionally not `Send` because web hosts wrap JS promises.
- Frames and samples are addressed by integer index; convert from `Time` with `frame_index` / `sample_index` (ADR 0010). A `VideoFrame` carries `data: FrameData::{Cpu(RgbaFrame), Gpu(GpuFrameHandle)}` (see Frame variants); audio is interleaved i16.
- Hosts implement the traits: WebCodecs (web), libav/OS codecs (desktop), WebView or MediaCodec/VideoToolbox plugins (mobile). The engine tests with `FakeDecoder` (numbered frames, integer-only triangle tone, bit-identical on every platform).
- `FrameCache`: one per source, LRU, hard byte budget. `get_or_decode(decoder, index, lookahead)` returns a hit or decodes, then prefetches up to `lookahead` frames, clamped to what fits in the budget and to the end of the stream; the requested frame is never evicted by its own prefetch.

## Frame variants (S1 recommendation, ADR 0004)
- `FrameData::Cpu(RgbaFrame)`: RGBA8 in a shared `Arc<[u8]>` (software decoders, tests, export readback).
  `FrameData::Gpu(GpuFrameHandle)`: opaque, shared, **close-on-drop** reference to a frame in GPU or decoder memory: a JS `VideoFrame` on the web, a platform texture / hardware buffer natively.
  The host implements `GpuResource` (a one-method `Any` trait) and releases the resource in its `Drop` (`VideoFrame.close()` on the web), so an evicted or dropped frame frees GPU memory at once. The renderer imports it by `downcast_ref::<HostType>()`; the engine never looks inside. Handles are `Rc`-based, deliberately not `Send`.
- A decoder advertises `frame_kinds()` (`FrameKinds::{CPU, GPU, BOTH}`; default CPU only) and the caller picks one with `set_frame_kind(kind)` (`Unsupported` if not offered). Hosts that cannot do GPU frames need change nothing.
- `FrameCache` charges `VideoFrame::byte_size()`: pixel bytes for CPU, the handle's `est_bytes` for GPU (`GpuFrameHandle::estimate_bytes(w, h)` = 4 B/pixel, conservative; a host that knows better passes its own). One budget covers both variants; eviction, `set_budget` and `clear` drop the frame, which closes the GPU resource.
- `FakeDecoder` offers both (`set_frame_kind`), and `live_gpu_frames()` counts fake GPU frames not yet closed so tests can assert release.

## Edge cases
- A frame larger than the whole budget is returned but not stored. `set_budget` evicts immediately (memory-pressure hook).
- Out-of-range index -> `MediaError::OutOfRange`; missing codec -> `Unsupported` (UI states it plainly).
- Budget choice (default per device class) is a host decision, not made here; proxies are not planned for M1.

## Tests (`crates/media/tests/cache.rs`)
Determinism, hit skips decode, look-ahead and its clamps, LRU order, oversize frame, **budget never exceeded across 5000 random accesses (incl. shrinking the budget mid-run)**, hit-path timing.

## Results
Cache hit path (debug build, includes LRU touch): ~1.2 us/op; test asserts < 20 us to stay stable on slow CI. Release is far lower.

## Demux and probe (M1-012)
`app_media::probe(&impl Source) -> Probe` (`crates/media/src/demux/`). Detects the container by magic bytes, reads the index (MP4 `moov`) or walks cluster headers
(WebM; payloads are never read, only each block's 4-byte header) and returns, per track: WebCodecs codec string, `codec_description` bytes
(avcC / hvcC / AudioSpecificConfig / OpusHead), coded size, `rotation` (0/90/180/270 clockwise, from the `tkhd` matrix), sample rate / channels, container
timescale, duration, `nominal_fps`, `vfr`, and the **packet table** (`pts`, `dts`, `duration`, `offset`, `size`, `keyframe`) in decode order.
`Probe::media_info()` gives the `MediaInfo` summary the `Decoder` trait uses. `MemSource` wraps a byte slice (tests, fuzzing, small files).
- **Hand-rolled, no dependencies.** `mp4`/`re_mp4`/`matroska-demuxer` read through blocking `Read + Seek`; our `Source` is async (browser Blobs, network ranges), so adapting them
  means buffering whole files. A read-only parser for just the index is ~1600 lines with comments, adds no licence or wasm-size surface, and is simple to bound. Revisit if lacing turns out to matter.
- **Time (ADR 0010).** Every timestamp is `Time` ticks: `value * 705_600_000 / timescale` in 128-bit, rounded to nearest, computed from the *absolute* dts (no accumulated drift).
  30 fps in a 15360 timescale gives exactly `23_520_000` ticks per frame; WebM's millisecond timestamps stay whole milliseconds (33, 33, 34 ms) because that is what the file says.
  The first `elst` edit is applied (leading empty edit delays, first real `media_time` is subtracted), so B-frame files start at pts 0 with negative dts, like ffprobe.
- **VFR.** Video `vfr = true` when any frame step differs from the most common step by more than max(1 timescale unit, 1%) (final sample excluded; MP4 from `stts`, WebM from sorted pts).
  Then `nominal_fps` is `None`; otherwise it is the exact rational (MP4: timescale / step; WebM: `DefaultDuration`, else average), snapped to a standard rate within 0.1%.
- **Codec strings.** `avc1.PPCCLL`, `hvc1.<space><profile>.<compat>.<tier><level>.<constraints>`, `vp09.PP.LL.DD`, `av01.P.LLT.DD`, `vp8`, `mp4a.40.<aot>`, `mp3`, `opus`, `vorbis`, `flac`; unknown codecs
  return their lowercase fourcc / Matroska id and the host decides (`Unsupported`).
- **Fragmented MP4** (phones, screen recorders, browser `MediaRecorder`, `frag_keyframe+empty_moov`): when `moov` has `mvex`, or a `moof` appears, the probe walks the top-level boxes and reads each `moof` (header bytes only, never `mdat`, 256 MiB cap in total).
  Per `traf`: `tfhd` (base offset, default duration/size/flags), `tfdt` (base decode time; without it the previous fragment's end), `trun` (data offset, first-sample flags, per-sample duration/size/flags/composition offset v0 and v1); defaults fall back to `trex`.
  A sample is a keyframe unless its flags have the non-sync bit. Sample offsets are relative to the `tfhd` base-data-offset, else the start of the `moof` (every real muxer writes `default-base-is-moof`; the legacy "end of the previous traf" rule is not implemented).
  `sidx`/`mfra` are ignored (the probe reads every `moof` anyway). VFR, nominal fps and duration are computed from the fragment samples (a fragmented file has no `mvhd`/`mdhd` duration). A fragmented muxer writes no negative composition offsets, so a B-frame file starts at pts = the reorder delay, not 0.
  **Cut short:** unlike a plain MP4 (no `moov` = error), a fragmented file whose tail is missing keeps every complete fragment before the cut (a crashed recording is still importable); a `moof` or sample reaching past the end of the file ends the walk.
- **Matroska lacing (Xiph, EBML, fixed-size) is not supported** and stays a plain `Unsupported`: block timecodes are whole container units (ms), a laced block needs sub-unit timestamps from `DefaultDuration`, and it is
  essentially never used for video or for Opus/Vorbis in files from current muxers. Revisit if a real file needs it (follow-up issue).
- **Not supported (plain errors):** QuickTime sound entry v2, Matroska lacing, encrypted tracks, tracks other than video and audio (ignored). Matroska rotation (Projection) is not read: `rotation` is 0 for WebM.
- **Hostile input.** Never panics; returns `MediaError::Invalid` (malformed/truncated) or `Unsupported`. Counts are checked against bytes present, packets per track are capped (`MAX_PACKETS_PER_TRACK` = 2 M), `moov`
  at 256 MiB, tracks at 64, a sample outside the file is an error. A file cut anywhere before its index or inside its media data is an error, not a partial result.
- **WASM-safe.** `std` only, no threads/fs/time; `cargo build -p app-media --target wasm32-unknown-unknown` is clean. A host `Source` may return short reads.

## Web decoder (M1-016)
`HostDecoder<H: PacketDecoder>` (`crates/media/src/host.rs`) is the `Decoder` for every host that decodes compressed packets itself. **Rust plans, the host decodes.**
- **Rust** (native-testable, `crates/media/tests/host.rs`): frame index to packet (presentation order), the **pre-roll** (latest keyframe at or before the target whose pts is not after it, so an open-GOP leading frame starts one GOP earlier), the packets from there through the target in decode order (`VideoRequest`), and for audio the packets covering `[start, start+count)` plus up to 4 priming packets (`AudioRequest`). Timestamps given to the host are unique microseconds (`ticks_to_us`).
- **Host** = `WebCodecsHost` (`packages/engine-client/src/decode/host.ts`, runs in the engine Worker; only engine-client touches WebCodecs): reads packet bytes with `Blob.slice` (`blob-source.ts`; a contiguous GOP is one range read, far-apart packets separate reads, a 64 MB file opens by reading a sliver), `reset` + `configure` + feed + `flush`, keeps the frame whose timestamp is the target and `close()`s every intermediate. Wasm glue: `crates/wasm/src/media.rs` (`MediaFile`, `FrameRef`); TS entry `Engine.media.open(file)` -> `MediaHandle`.
- **Frame kinds.** `gpu: true` (default) returns `DecodedFrame{kind:"gpu", frame: VideoFrame}`; `frameKind` is `"cpu"` when the host has no `VideoFrame` or `gpu:false` (RGBA via `VideoFrame.copyTo`, visible rect only). The GPU frame sits in the host's id table behind a `GpuFrameHandle` whose `Drop` calls `release(id)` = `VideoFrame.close()`; `DecodedFrame.release()` drops it. Whether the renderer can import it (`importExternalTexture`) is the render crate's capability probe (S1), not decided here.
- **Cancellation.** `Handle.videoFrame` is latest-wins: a new call bumps a ticket and calls `host.cancel()` (decoder `reset()`, generation counter), so the running seek rejects at once with `MediaDecodeError` kind `cancelled` (Rust: `MediaError::Cancelled`), queued older ones reject without running, outputs of the stale generation are closed on arrival. Callers treat `cancelled` as "ignore". All calls on one file are serialised (the wasm object is borrowed across an await).
- **Back-pressure.** At most 8 packets (`decodeQueueSize`) wait in the decoder; the feeder waits on `dequeue` and re-checks the generation each time.
- **No leaks.** `Handle.stats()` = `{received, closed, open}`; `open` is 0 once every returned frame is released (the test asserts it after seeking every frame of every fixture in random order, a 24-call scrub burst with cancellations, and GPU frames held then released).
- **Audio** returns **f32 interleaved at the project rate** (`openMedia(..., {audioRate})`, default 48000): AudioDecoder output is placed by timestamp, resampled by linear interpolation when the rate differs (identity, bit-exact, when equal), silence where nothing decoded. The Rust `Decoder::audio` still narrows to i16 for the existing trait; `HostDecoder::audio_f32` and `MediaFile.audio` keep f32. **Opus pre-skip:** Chrome drops the pre-skip from the first output after every `configure`, which mid-stream would shift audio 6.5 ms early; the host adds it back unless the request starts at the stream's first packet (`AudioRequest.from_start`). Found by the test (83 vs 88 zero crossings), fixed.
- **Errors.** Unsupported codec fails at `open` (`VideoDecoder.isConfigSupported`), kind `unsupported`, message names the codec in plain words and by string ("This device cannot decode H.265 (HEVC) video (hvc1...)"); garbage is `unsupported`/`invalid`, a decoder fault is `io`. The Tauri backend returns `unsupported` ("not available yet, native decoder M1-015").
- **Playback (M1-033):** `MediaHandle.stream(startIndex)` is a sequential decode (one decoder run, each frame decoded once, back-pressured) and `frameIndexAt(ticks)` picks frames by timestamp (VFR-correct); see `preview.md`. `videoFrame` still restarts at the keyframe per call (scrub/step).
- **Not done (follow-ups):** a decoded-frame cache around the playhead for scrubbing (M1-013), frames are returned in coded orientation (the preview applies `rotation` in the compositor; the timeline thumbnails apply it in `engineMediaHost.thumbnail`), higher-quality audio resampling than linear, VFR-to-CFR mapping (`frame_count` = packets), hardware-decode preference (`hardwareAcceleration` left at the browser default).

### Test (`tests/smoke/decode.spec.ts`, runs in `npm run smoke`; needs `npm run build:wasm`)
Headless Chromium, the harness (`decode-harness.ts`) bundled with esbuild and run in a **Worker**, on H.264/AAC MP4, MOV, fragmented MP4, VFR MP4 and VP9/Opus WebM. Frame identity: every frame of every file fetched by a **random-order seek** (seeded) is byte-identical to the same frame from an **independent linear decode** (a bare `VideoDecoder`, packets front to back, no seeking), indices and pts are right and strictly increasing, and all frames of a file are distinct (so a neighbour swap cannot hide). Plus: cancellation burst, zero open frames, GPU handle lifetime (`instanceof VideoFrame`), audio length / 440 Hz crossings at 48 and 44.1 kHz, 64 MB file read < 1 MB, unsupported-codec message. Unit tests: `tests/unit/decode.test.ts` (errors, range grouping, stale abort, resample/assemble).
**Numbers (headless Chromium 1243 in a 4 vCPU sandbox, software decode, no GPU; 160x120 fixtures, GOP 15 so not representative of 1080p):** seek p50 about 3-4 ms, p95 about 4-6 ms. The 1080p budget (S1: < 50 ms warm) is NOT judged here; it needs reference hardware (ADR 0004 "must be confirmed").

## Waveform peaks and thumbnails (M1-013)
**Rust: `app_audio::peaks`** (`crates/audio/src/peaks.rs`; PCM in, no I/O). `PeaksBuilder::push(&[i16])` takes interleaved PCM in any chunk size and keeps the min/max envelope across all channels per **256-frame bin**; `Peaks` derives a power-of-two pyramid above it (512, 1024, ... frames per bin, up to level 20). `Peaks::columns(start_frame, frames_per_px, count)` returns one `[min, max]` per pixel column from the coarsest level not wider than a pixel (`min > max` = no data yet), so drawing costs O(pixels) however long the clip is.
- **File format** (`peaks/<fingerprint>.bin`, header in the module docs): `OCPK`, version 1, flags (bit 0 = complete), base 256, sample rate, frames, then `[i16 min, i16 max]` per bin. Only level 0 is stored (4 B per 256 frames, about 2.6 MB per hour of audio at 48 kHz, 1/64 of mono PCM); upper levels are derived on load in one pass. The reader checks every length, refuses newer versions, never panics (tested with every truncation, forged counts, bit flips). The container keeps the reserved `peaks/<media id>.bin` entry for a later bundling of this file (project-file.md); the cache is the source of truth for now.
- **Partial and resumable**: `snapshot()` is a valid file flagged incomplete (the partial bin included); `PeaksBuilder::resume(bytes)` drops a trailing partial bin and continues from `next_frame()` (a multiple of 256), so an interrupted job costs at most one chunk.
- **Speed**: 60 s of 48 kHz stereo in 1.8 ms (about 34,000x realtime, release, `cargo test --release -p app-audio throughput -- --ignored --nocapture`). The real cost is the decoder, not this.
- **Engine API**: `Engine.peaks.begin(sampleRate, channels, resume?) -> PeaksJob {nextFrame, push, snapshot, finish, dispose}` and `Engine.peaks.open(file) -> PeaksView {sampleRate, frames, complete, columns(), close()}`; wasm classes `PeaksJob` / `PeaksView`, Tauri commands `peaks_job_*` / `peaks_view_*`. (Tauri currently receives PCM as JSON number arrays; once the native decoders land, decoding and extraction should stay in Rust and never cross IPC: follow-up.)

**Web layer (`apps/web/src/media/`)**
- `MediaHost` (`host.ts`) is what the media layer needs from a decoder: `audioFormat`, `readAudio(start, frames)`, `thumbnail(seconds, w, h)`. **`engineMediaHost(open)` (`engine-host.ts`) adapts an `Engine.media` handle (M1-016: f32 PCM to i16, thumbnails from `videoFrame(frameIndexAt)`; rotation not applied yet) but is **not wired to the media bin yet** (follow-up: resolve each `MediaRef` to the bin's open handle). Until then `Timeline.tsx` serves only the sample project's synthetic media (`FakeMediaHost` behind `onlyFixtures`); imported files keep placeholders, never made-up data.
- `extractPeaks` (`peaks-job.ts`): decodes 2 s chunks, pushes them to the builder, publishes a snapshot at most every 400 ms (cache + `onFile`), yields to the event loop between chunks, honours an `AbortSignal` (the partial file stays cached) and resumes from a cached partial file. A complete cached file short-circuits without decoding. `WaveformService` runs at most 2 jobs at once and parses each published file into a `PeaksView`.
- **Cache** (`cache.ts`): `MediaCache` over a `BlobStore`: OPFS in browsers (the webview inside the Tauri shells has it too, so the shells use it for now rather than a native app cache dir: follow-up if a native decoder wants to write there), memory otherwise. Keys are `peaks/<fp>.bin` and `thumb/<fp>/<interval>/<k>.webp`; `fp` is the media's content hash, else its locator. LRU by recency with a **256 MiB default limit**; an entry larger than the whole limit is not stored; a failing store only means a recompute.
- **Thumbnails** (`thumbs.ts`): 160x90 WebP (quality 0.72) at the step from `INTERVALS` (0.25 s ... 40 min, neighbouring steps at most 2.5x apart) that makes a slot at least one thumbnail wide at the current zoom; produced lazily for visible slots only (3 parallel, newest request first, 48 queued at most), kept as `ImageBitmap`s (600 in memory, oldest evicted and closed) and on disk.

**Wiring (M1-013b):** `importedMediaHost(engine, fileOf)` adapts `Engine.media` handles to `MediaHost` using the media bin's `fileOf`; `Timeline` routes `fixture:` uris to the synthetic host and everything else to it (`routeMedia`). Thumbnails honour `MediaHandle.info.video.rotation` (clockwise degrees; 90/270 swap the output to portrait). Unit tests: `tests/unit/engine-host.test.ts` (`thumbPlan`, host); smoke: `tests/smoke/media-bin.spec.ts` ("imported clip's waveform is real"). Handles are not closed when media leaves the project yet (follow-up).

## Native decoder (desktop, M1-015)
`Engine.media` in the Tauri shell is libav (`apps/desktop/native-media`, ADR 0004 "S4 results") behind the same `PacketDecoder` / `HostDecoder` as the web: the Rust demuxer plans packets, libav decodes them (CPU RGBA frames, `frameKind: "cpu"`). Same `MediaFileInfo`, same errors (`unsupported` names the codec). A `Blob` with a `path` (dialog / drop) is decoded in place; any other is staged to a temp file first. The first request in a GOP decodes the whole GOP and caches its raw frames (<= 384 MB), so sequential access is linear. Opus mid-stream alignment is within 1 ms (container timestamps). Hardware decode and GPU frames: follow-up. The `native-media` cargo feature is off by default; without it the commands do not exist and `media.open` rejects `unsupported`.
