# Feature: preview panel and playback (M1-033)

Code: `apps/web/src/PreviewPanel.tsx` (UI, keys), `apps/web/src/preview/` (`player.ts`, `timing.ts`, `compositor.ts`, `layout.ts`, `audio.ts`, `audioMix.ts`, `useMediaHandles.ts`), engine-client `decode/stream.ts` + `decode/frames.ts`.

## Behaviour
- **Audio is the master clock.** Position = anchor + (audible audio clock - anchor time) x rate, with the audible clock = `AudioContext.getOutputTimestamp()` extrapolated (else `currentTime - outputLatency`). It is computed from the clock, never accumulated per frame, so video cannot drift. If the context cannot start (no Web Audio, blocked), the run uses `performance.now()` and is silent.
- **Per frame** (rAF): wanted frame = `floor(position)` on the sequence grid (ADR 0010, same quantisation as `evaluate`). If it differs from the last drawn: `evaluate(t)` -> for each layer the decoded frame -> compositor -> canvas. One draw at a time: if the clock moved on while drawing, the intermediate frames are **skipped and counted as `dropped`**, never waited for. A layer whose frame is not decoded yet holds its previous frame (`stalls`).
- **Decode while playing**: one `MediaHandle.stream()` per clip (sequential decoder, each frame decoded once, pre-roll from the keyframe). Prefetch depth = `prefetchFrames(byteBudget, w, h)` (default 192 MiB budget, 2..12 frames, a clip never holds more); frames the clock passed are released. A clip coming into view within 0.5 s gets its stream started early (cuts do not stall for a GOP). Jumping back or falling far behind restarts the stream at the wanted frame.
- **Paused (scrub, step)**: `videoFrame(index)` per request, latest wins (older requests reject `cancelled` and are ignored). `seek` while playing pauses.
- **Phone media**: the probe `rotation` (clockwise 0/90/180/270) is applied in the compositor (`layout.textureMatrix`, exact at right angles); the layer's display size swaps width/height for 90/270, and the import (media bin) sizes the sequence from the display size. Frames are chosen by **timestamp** (`frameIndexAt` = last frame with pts <= source time, binary search over the sorted pts), so VFR clips play at real speed and hold each frame for its real duration. Frame rate repeat/skip for 24-in-30 etc. falls out of the same rule.
- **Audio**: chunks of 0.2 s mixed from `evaluate(t, n).audio` (gain, offset, speed by linear resample, mono to stereo, soft limiter), scheduled as `AudioBufferSource`s on the context clock, kept 0.8 s ahead. A chunk that is late when ready is trimmed to the clock (`audioTrimmed`), never shifted. Audio plays at 1x only; shuttle speeds and reverse are silent.
- **Transport**: Space play/pause; J/K/L shuttle (L repeated = 2x, 4x; J = reverse 1x/2x/4x; K stops; opposite key restarts at 1x; reverse is video only, one `videoFrame` per frame, so it drops frames on slow decoders); `,` `.` and Left/Right (when no slider/button has focus) step one frame; Home/End; buttons: start, previous frame, play (44 px), next frame, end. Timecode `HH:MM:SS:FF` (left-to-right even in RTL), non-drop-frame labels for 29.97/59.94 (nominal 30/60). Scrubbing the timeline playhead calls `seek` for every pointer event. A speed badge shows `2×`, `-4×`. Playback stops at the end; Play at the end restarts.
- **Canvas**: WebGL2, backing size = CSS box x devicePixelRatio, never above the sequence size or 1920 on the long edge; the box takes the sequence aspect (the aspect selector applies only while the project has no clips). Layers use the engine's `Layer` semantics (centre, scale of display pixel size, rotation, opacity), so the preview matches export.
- **One shared project (M1-024).** The preview plays the project in `store/projectStore.ts`; there is no "open a clip" path (import goes through the media bin, and the empty preview shows the same import button, `preview-import`, which feeds the same flow). One `Player` lives for the preview; when the shared project changes (edit, undo, redo, import, recovery) or a decoder handle becomes available, `Player.reconfigure` takes the new rate, size, length and sequence, drops all decode feeds and redraws the playhead's frame (clamped to the new end). Playback that is running carries on from the same frame, re-anchored on the new timeline (a clip played past the new end just stops there); the new duration shows without a restart. Decoder handles (`useMediaHandles`) are opened lazily from the bin's file for each audio/video media item of the project and closed when the item leaves it (undo of an import). The playhead frame is the store's `playhead`; the player publishes into it and follows changes made elsewhere. An empty project shows the idle 60 s sample length. Desktop (Tauri): `media.open` rejects `unsupported` with "not available yet (native decoder, M1-015)"; the bin reports it.
- Test hook: `window.__overcutPreview` = `{ player, stats(), probe(x, y), media() }` (read-only numbers, no network).

## Decisions and deviations (told to the manager)
- **WebGL2 compositor in TypeScript, not the Rust wgpu one.** `app-render` is not bound into `app-wasm` yet (and WebGPU is not universal); WebGL2 runs everywhere M1 targets and gives GPU upload of `VideoFrame`s (`texImage2D`). The semantics mirror `app_render::Layer`; swapping in wgpu-on-canvas (with WebGPU first) is a follow-up behind the `Renderer` interface. No WebGPU path yet.
- **Prefetch byte budget is a TS window per clip**, not the Rust `FrameCache` (not bound to wasm; M1-013 owns the scrub cache).
- Decoding and compositing run on the main thread (WebCodecs decodes off-thread, reads are async); moving the player into the engine Worker is a follow-up.
- Colour: the browser converts YUV to sRGB on upload (BT.709/601 per stream); no HDR.

## Edge cases
No GPU context: black preview and a plain message. Media without video: black + audio. Layers beyond the clip: black. Decoder fault: message under the preview, playback continues. Clip shorter than the sequence repeats nothing (black). Resize clears the canvas, so a paused preview redraws. Pause closes every stream and held frame (`stats().open` returns to 0; test).

## Tests
Unit `tests/unit/preview.test.ts`: frame/tick maths, timecode, clock (forward/reverse/clamp/no drift), JKL, prefetch depth, rotation mapping (all four angles, four turns = identity), placement, canvas size, VFR timestamp selection, audio mixing; `tests/unit/project-store.test.ts`: `Player.reconfigure` takes a new length and rate. End-to-end follow-up of the shared store: `tests/smoke/project-store.spec.ts`. Smoke `tests/smoke/preview.spec.ts` (fixtures in `crates/media/tests/fixtures`, `flash_click.mp4` = a white frame and a 1 kHz click both at 1.000 s): portrait rotated clip is upright and portrait-shaped; Space plays 2 s then pauses, `.`/`,` step one frame, Home, 40 random scrubs; L,L = 2x, K stops, no leaked frames.

## Numbers (headless Chromium, software decode and SwiftShader GL, fake audio sink, 320x180: NOT representative of devices)
Play 2 s: 57 frames presented, 0 dropped, 0 stalls, 30.0 fps, max lateness 12-20 ms (p95 9-18 ms; one run with 2 dropped / 44 ms while the GPU readback probe was running). A/V offset of the flash frame against the audio clock: 22-33 ms (one frame period of quantisation; this is the audio clock, not an acoustic loopback). Scrub (paused, random frames, GOP 30): p50 ~9 ms, p95 ~11-16 ms. The 1080p budgets in `PERFORMANCE.md` still need reference hardware.
