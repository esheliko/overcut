# Privacy: no network beyond our own assets (M1-042, XT-06)

**Behaviour.** OverCut loads only its own files from its own origin. Editing, playback, import and export never contact a server. After the first visit the installed app opens and edits with the network off.

**Allow-list.** `config/network-allowlist.json`: `sameOrigin: true`, `hosts: []` (the web build), `desktopOnlyHosts: ["ciscobinary.openh264.org"]` (the desktop app, after a click; see below). The web smoke test reads only `hosts`. Adding a host needs a reason in `docs/` (ADR or this file) in the same PR, and the feature using it must be optional with a local fallback (PRODUCT.md, ADR 0005).

**Test.** `tests/smoke/network.spec.ts` (desktop project, production build) records every request of the page, its Workers and the service worker through: load, import a fixture, edit (aspect ratio), play, export + save, `/diagnostics` (visited if it exists), then an offline reload with an import and an edit. It fails on any http(s)/ws(s) request to a host outside the allow-list and on any Content-Security-Policy violation. `data:` and `blob:` URLs never leave the device and are not counted.

**CSP.** `apps/web/csp.ts`, injected as `<meta http-equiv="Content-Security-Policy">` into the production `index.html` by the `overcut-csp` plugin in `vite.config.ts`: `default-src 'self'`; `script-src 'self' 'wasm-unsafe-eval'` (WebAssembly only; no inline scripts); `worker-src 'self' blob:`; `connect-src 'self'` plus Tauri's local `ipc:` / `http://ipc.localhost`; `img-src`/`media-src` with `blob: data:`; `style-src 'self'`; `object-src 'none'`; `base-uri 'none'`; `form-action 'none'`. Not applied in dev (inline React refresh script, HMR WebSocket).
- **Limit of the meta tag:** it cannot set `frame-ancestors`, and does not govern the service worker script itself. A real response header (`vercel.json`) is stronger: filed as a process request.

**Offline.** Measured: after the first visit the app reloads, imports and edits with the network off. Two causes had broken it, both fixed: (1) files loaded before the service worker took control (JS chunks, engine `.wasm`) were never cached, so `main.tsx` re-requests each same-origin file once the worker controls the page (from the HTTP cache, no new download); (2) the server sends `Vary: Origin`, so the cached copy did not match module-script requests, and `sw.js` now matches with `ignoreVary`. The spec asserts every loaded file is in the cache before going offline.

**Network activity log (XT-06).** App menu > Privacy and a section on `/diagnostics` list every request of this session: time, address, size, and who started it (app file, background worker, service worker, your download). It says "OverCut made no requests outside its own files" when that holds, and names any other host otherwise. Sources, none wrapping `fetch`: a `PerformanceObserver` on resource entries in the page (`apps/web/src/privacy/networkLog.ts`); Workers (preview, export) and the service worker report their own resource entries on a `BroadcastChannel` (`reportWorkerNetwork`, `packages/engine-client/src/net-report.ts`; the service worker has an inline copy in `sw.js`). The list is in memory only (cap 500), cleared on reload, never stored or sent. Blob/data URLs are not shown. Limits: cross-origin sizes can be 0/unknown; native (Tauri) requests are invisible to the browser, so Rust-side code must report them (below).
- **Hook for the desktop app:** `recordNetworkEvent({ url, bytes?, initiator: "user-download" })` from `apps/web/src/privacy/networkLog.ts`. Call it when the user-started download (OpenH264, M1-041) begins or ends; it then appears in the log, and the summary names the host. Test: `tests/unit/network-log.test.ts`; smoke step in `network.spec.ts`.
- **Opt-in crash reports** moved to M2 (XT-06b): they need a server endpoint. Design then: off by default, a documented optional endpoint listed in the allow-list, always with a local fallback ("Copy crash report" to clipboard or file), and every send visible in this log.

**Edge cases.** A future opt-in crash report or update check (XT-06) must be off by default, listed in the allow-list with its reason, and shown in the network log above.

## Desktop app: the one optional download (M1-041, decision of the work manager, 2026-11-23)
Cisco's OpenH264 binary is royalty-covered only when downloaded from Cisco (ADR 0004), so on a computer **with no hardware H.264 encoder** MP4 export needs one network call. It is **opt-in and desktop-only**:
- The export dialog defaults to "WebM (VP9), works offline" and shows a notice plus an explicit button, "Enable MP4 (H.264): downloads the free OpenH264 codec from Cisco, about 1 MB, once". **Nothing is downloaded without that click**; declining costs nothing (WebM works, the rest of the app is unaffected).
- Host: `ciscobinary.openh264.org`, listed under `desktopOnlyHosts` (not `hosts`: the web smoke test and the CSP are for the web build, and a desktop-only entry must not widen them). One HTTPS GET of one file (about 1 MB), no cookies, no redirects, user agent `OverCut`; nothing about the user, project or machine is sent. `tests/unit/desktop.test.ts` checks the list and that it matches the constant in `openh264.rs`.
- The download is checksum-verified (SHA-256 of Cisco's `.bz2`, pinned in the app per release), unpacked, and stored once in `<app data>/openh264/<version>/`. A stored copy is loaded at start-up with no network call. A checksum mismatch, an HTTP error or no connection leaves nothing behind and the dialog says so; Cancel stops it between chunks.
- **Status:** built (issue #57): the downloader, progress, cancel and failure messages, tested offline with a fake server. **The pinned digests are empty until someone with access to Cisco's release page fills them in**, so the button stays hidden and the app still never touches the network. See `docs/features/desktop.md`.

**Install (PM-12).** The "..." menu offers **Install app** only after the browser fires `beforeinstallprompt` (Chromium on desktop and Android); the event is kept and the browser's own mini-bar is suppressed, so nothing appears unasked and nothing is a network call. On iPhone/iPad (no such event in Safari) the menu shows **Add to Home Screen**, which opens a local how-to sheet (Share > Add to Home Screen). Nothing is offered when the app already runs standalone or inside the desktop shell. Code: `apps/web/src/install.ts`, `AppearanceInstall.tsx`; tests: `theme.test.ts` (`installKind`, `isIos`), `tests/smoke/appearance.spec.ts`.
