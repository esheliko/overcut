# Feature: projects, canvas, versions and history (PM-01, PM-06, PM-07, TL-06)

## Behaviour
- **Projects home** (`apps/web/src/project/ProjectsHome.tsx`): shown when no project is open (after deleting the open one, or "Projects" in the "…" menu). One card per project: thumbnail (first picture), name, length, canvas size, last edited. Actions: **Open**, **Rename** (inline, Enter/Esc), **Duplicate** ("Name copy"), **Export project file** (`.overcut`), **Delete** (confirm sheet; removes the project, its versions and journals, never the media files). Top: **New project** and **Open project file**. A damaged or non-project file is refused with a message and nothing is added; a newer-format file opens read-only (`project-file.md`).
- **No Save button.** Autosave is the norm (`persistence.md`); the top bar shows **Saved** / **Saving…** / **Not saved** under the project name (`data-testid="save-status"`). The project name lives in the list (`ProjectLibrary`); it is stamped into the file on export and duplicate.
- **New project** (menu, or the home): a sheet with the name, canvas chips (**Match first clip** = default, 16:9 1080p, 9:16, 1:1, 4:5, 4K 16:9) and frame rate chips (Match first clip, 24, 25, 30, 50, 60). A chosen canvas or rate is kept when the first clip is imported (`importOps(..., keep)`); "Match first clip" keeps the old behaviour (the first picture sets size and rate).
- **Canvas later** (PM-01 "changeable later"): the aspect picker in the preview now changes the real project canvas through `set_sequence_format`: one undoable step, named "Change canvas to W×H" in History. It also marks the size as chosen. Clips are not rescaled yet (they follow the compositor's fit; fit/fill/scale options are TL-24, M2).
- **Versions** (menu: Versions…): "Save version" with an optional name; the list shows named and automatic ones with date and size; **Restore** replaces the current content by the snapshot as ONE undoable edit (`restoreOps`: media added/removed/relinked, canvas, and every clip that differs deleted and re-inserted; atomic). Before restoring, the current state is saved as the named version "Before restore", besides the Undo step. Restore is refused (message, nothing changed) when the snapshot has different sequences/tracks (no op creates tracks yet).
- **History** (menu History, plus a top-bar button on wide layouts; on a phone it lives in the "…" menu): the edits of this session by name ("Split clip", "Trim end of Beach.mp4", "Import Beach.mp4", "Change canvas to 1080×1920"), current step highlighted, later steps (after undo) dimmed. Click or Enter on a step goes back or forward to it (a run of ordinary undo/redo, so the journal and the undo buttons stay in agreement); Up/Down move between steps. A session recovered after a crash shows a note: edits from before can still be undone with Undo but are not named.

## Data
- **Library** (`packages/engine-client/src/persist/library.ts`): the list is a JSON document in `localStorage` key `overcut.projects.v1` (id, name, times, seconds, canvas, fps, `fixSize`/`fixRate`, thumbnail data URL ≤ 40 KB) plus `overcut.project.current` (last open id; unset = the legacy project `default`; empty = home). It holds only what the home shows; the project data is never in it. Fails soft: blocked storage means an in-memory list for the session; a damaged index reads as empty (the projects are untouched). The legacy single project `default` appears in the list the first time it opens.
- **Project ids** are `p-<random>` (letters, digits, `-`, `_`), one storage folder each (`openProjectStorage(id)`); `acquireProjectLock(id)` per project. Switching projects closes the old session fully (clean save) before the next opens, because the engine has one editor.
- **Versions** (`persist/versions.ts`): `versions.json` (atomic) lists `{id, name|null, auto, at, size}`; each snapshot is a whole `.overcut` file `v-<id>.overcut` (atomic). Order on save: file, then list, then pruned files, so a crash leaves at worst an unlisted file. Automatic snapshots: every **10 minutes** while the session made edits since the last one (skipped when identical to the newest); keep the **newest 20** automatic ones and every named one; total size cap **64 MiB** (oldest automatic first, then oldest named; the newest always stays). Naming an automatic version keeps it. `?e2e&autoversion=<ms>` shortens the interval in tests.
- **History** (`store/history.ts`, `projectStore.ts`): the store mirrors the engine's undo stack with names (`describeOps(ops, projectBefore)` returns a catalog key and values, so names are translated); a coalesced drag is one entry. Not persisted; a reload starts a new list (the engine journal still undoes further back).

## Project files
- Export: `session.snapshot()` (open project) or `projectBytes(engine, id)` (home: opens, recovers and folds the project, then closes) -> `deliverProjectFile`: **desktop** native Save dialog (`desktop_save_project_file`), **web** a download `<name>.overcut`.
- Open: **desktop** native Open dialog (`desktop_open_project_file`, 256 MiB cap), **web** a file chooser. `importProject` validates with `Engine.openProject` before storing anything, stores a new project id, and keeps media references as they are (media is never embedded: on another device the clips show as offline and Relink applies, `media-bin.md`).

## Edge cases
Delete of the open project goes home. Two windows: the per-project lock still applies. A project whose files are gone cannot be duplicated or exported (message). Names are trimmed and capped at 60 characters. A restore while an export runs is refused (the project is frozen).

## Test plan
`tests/unit/projects.test.ts` (library, copy names, versions pruning and caps, restore ops applied against a reference applier that enforces id/overlap/media rules, history names and steps, `jumpTo`, canvas presets and `importOps` keep rules); `tests/smoke/projects.spec.ts` on phone and desktop (new project with chips, real canvas and Undo, history click and keyboard, versions save/restore/undo, home rename/duplicate/export/open file/refuse bad file/delete confirm/empty state, 44 px targets, no overflow). Native dialogs are compile-checked only (`desktop-check`).

## Not covered / follow-ups
21:9 and custom canvas sizes (PM-01 lists them; the sheet has the five M1 presets); renaming a version from the list; thumbnails refresh only while the project is open; a project's media handles are per device; "Save as" of a version to a new project.
