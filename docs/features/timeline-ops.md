# Feature: edit operations (`app-timeline`, M1-003 / spike S7)

## Behaviour
The project changes only through `apply(&mut Project, Op) -> Result<Inverse, OpError>` (ADR 0006). `Op` is a serializable enum addressed by id: `InsertClip`, `Split`, `TrimIn`, `TrimOut`, `Move`, `Delete`, `SetClip` (exact geometry; used by inverses, also a valid edit), `SetMedia` (uri + fingerprint of a media file; import and relink), `SetLink` (linked picture and sound, below), and the track ops `AddTrack`, `RemoveTrack`, `MoveTrack`, `SetTrackProps` (M2-002; see `model.md`). The M2-005 ripple family (below) are new variants (`#[non_exhaustive]`, JSON tag `op`). Not versioned: additive, old projects never contain them.
- **Validation before mutation**: unknown ids, locked track, new id already in the document, video/audio kind rules, `duration > 0` (in < out), `start`/`source_in >= 0`, speed > 0, source range inside the media (when its duration is known), no overlap on the destination track (touching is fine), no tick overflow. An error leaves the project byte-for-byte unchanged.
- **Ids come from the caller** (`InsertClip.clip.id`, `Split.new_id`): replaying the same ops on the same base gives the same state, and ops stay mergeable (M8).
- **Source offsets** scale by `speed` exactly; a speed that would need a fraction of a tick is refused (`InexactSpeed`), never rounded (ADR 0010).
- `Inverse` is a list of ops applied in order: insert -> `[Delete]`, delete -> `[InsertClip]`, move -> `[Move back]`, trim/`SetClip` -> `[SetClip old]`, split -> `[Delete right, SetClip left-old]`.
- `apply_all(ops)`: all-or-nothing; a failing step rolls the earlier ones back and the error names the index.

## Linked picture and sound (TL-05, minimal slice pulled into M1)
A video import puts its picture on V1 and its sound on A1. Those two clips carry the same `Clip.link` (a `LinkId`, 32 hex chars, optional and absent on unlinked clips; no schema bump, files from before it load with every clip unlinked). Only the editing layer acts on it: `evaluate` and export ignore it. Audio-only imports, a video without sound and stills are never linked.
- **Engine**: `InsertClip` carries the link (the import sets it; delete's inverse restores it). `Split { new_link }` gives the RIGHT part that link when the clip was linked (ignored otherwise); the left part keeps its link. The caller passes the same `new_link` for both halves of a pair, so the pieces stay linked pairwise; with no `new_link` the right part is alone. `SetLink { clip, link }` links or (with `null`) unlinks one clip; its inverse is `SetLink` with the old value. Every op still addresses one clip; a user action on a pair is ONE op list = one undo step (the engine already applies lists atomically).
- **Selecting** a linked clip selects its partner (click, tap, marquee, keyboard, Ctrl/Shift-toggle: both go on and off together; touch: a tap selects both). So delete, cut, copy, duplicate, nudge, drag-move and split-on-selection apply to both without further code. A link counts as ONE clip for "select one clip" rules (keyboard trim, the numeric timing dialog).
- **Trim** (drag an edge, keyboard, numeric timing) is applied to the clip and its unlocked partners by the same amount, in one step. The allowed range is what ALL of them allow (neighbours, source length). Split at the playhead splits every selected clip under it, or all clips under it when nothing is selected, so a pair is cut together and its pieces re-linked pairwise.
- **Copy / paste / duplicate**: copies of a pair get a new shared link; a copy whose partner was not copied is unlinked (never shares the original's link).
- **Escape hatch**: the Unlink button (clip tools row) turns the selected linked clips into independent ones (`set_link null`, one undo step); then a click selects one clip and edits affect only it. Re-linking is not offered yet (undo restores the link).
- **Edge cases**: a partner that was deleted (alone, after Unlink, or on a locked track) leaves a single clip that keeps its link id and edits alone, nothing breaks. A partner on a locked track is selected but not edited (locked tracks never change) and does not limit trims. If one half cannot take an edit (overlap, media end), the whole list is rejected and nothing changes. Dragging a pair to another track is not offered (only a single clip changes track).
- **Tests**: Rust (`crates/timeline/src/tests.rs` linked section, `crates/model` link round trip and old-file load, wire contract); TS `tests/unit/timeline-link.test.ts`; smoke `tests/smoke/activation.spec.ts` (one Delete cuts picture and sound).

## Ripple, roll, slip, slide (TL-04, M2-005)
Six ops (`crates/timeline/src/ripple.rs`). Each expands into primitive `SetClip`/`Delete` steps applied by `apply_all`, so it is atomic, its inverse is the combined inverse, and every step passes the ordinary checks: no overlap (touching is fine), `start`/`source_in >= 0`, source inside the media, `duration > 0`, integer ticks. **Nothing is clamped**: an edit that cannot fit is refused whole (`Overlap`, `EmptyClip`, `OutOfRange`, `BeyondMedia`, `TrackLocked`) and the project is unchanged. The UI computes limits itself and shows a rejected drag as not allowed.
- `RippleTrim { clip, edge: in|out, delta, all_tracks }`: `out` changes the length by `delta`; `in` moves `source_in` by `delta` (x speed), keeps the start and changes the length by `-delta`. Clips starting at or after the clip's OLD end move by the length change. Steps are ordered so none lands on an unmoved neighbour (grow: shift first; shrink: trim first).
- `RippleDelete { clip, all_tracks }`: delete, then pull clips starting at/after its end earlier by its length.
- `CloseGap { track, at, all_tracks }`: `at` inside an empty stretch (between two clips, or 0 to the first clip) closes it; `NotInGap` if `at` is on a clip or after the last clip.
- `Roll { left, right, to }`: `left` must end exactly where `right` starts on the same track (`NotAdjacent` else). The cut moves to `to`; both source windows follow, total length unchanged.
- `Slip { clip, delta }`: `source_in += delta` (source ticks); start and length unchanged.
- `Slide { clip, delta }`: the clip moves by `delta`; a neighbour that TOUCHES it (previous `end == start`, next `start == end`) gives or takes the difference at its adjacent edge; a non-touching neighbour is untouched and must not be overrun.
- **Sync rule** (`all_tracks`): false = only the clip's own track shifts. True = every other UNLOCKED track of the sequence also shifts its clips that start at/after the ripple point by the same amount; LOCKED tracks never move (they may drift out of sync, by design). A clip on another track that straddles the ripple point is not cut or moved; if shifting would overlap it, the whole op is refused. The clip's own track must be unlocked. Links are not read by the engine: the UI sends the partner's ripple in the same list (one undo step), or `all_tracks`.
- **Tests**: unit tests per op (both directions, edges at 0 and at source limits, locked, refusals); the S7 generator includes all six, so the property tests check validity after every op, `undo(do(x)) == x`, redo, journal replay and history. Wire examples in `edit-contract.json`.

## History and journal
- `History::apply(project, op, coalesce_key)`. Consecutive ops with the same `Some(key)` share one undo step (a drag is one Ctrl+Z). A new edit clears redo. `with_limit(n)` caps undo steps (journal is never trimmed).
- **Journal** = every op that changed the project, in order, *including* the ops that undo and redo apply, so `replay(base, journal) == state` has no special cases. JSON Lines (`journal_to_jsonl`/`journal_from_jsonl`; a torn last line is dropped, an earlier bad line is an error). Recovery from this op-only journal restores the document, not the undo stack; crash recovery uses the editor's commit log instead (`persistence.md`).
- A coalesced step keeps every inverse (undoing a 200-event drag applies 200 small ops); compressing same-clip runs is a follow-up if it ever shows up in a profile.

## Engine surface
`Editor` (JSON in, JSON out) wraps project + history; `crates/wasm` (`Editor` class), `apps/desktop/src-tauri` (`editor_*` commands) and `Engine.editing` (`packages/engine-client`, shared `createEditing` over both backends) all forward to it. Wire format pinned by `packages/engine-client/schema/edit-contract.json`, tested in Rust (`wire_format_matches_the_checked_in_contract`) and TS (`tests/unit/editing.test.ts`). `EditOutcome { revision, can_undo, can_redo, changed, patch? }` is returned after each call. `patch` (ADR 0020, `crates/timeline/src/patch.rs`) is what the edit changed: per changed sequence its shell and track order, per changed track its shell and one clip splice, the media list when it changed. The UI applies it immutably (`applyEditPatch`, unchanged tracks and clips keep their identity) and re-reads `project()` only when there is no patch or it does not fit (project id/name changed, a recovered session's first edit is fine: the shadow is re-based). The patch is made by diffing against a shadow copy, so it is the same for every op; pinned by `packages/engine-client/schema/patch-contract.json` (Rust test `patch_contract_matches_the_checked_in_file`, TS `tests/unit/edit-patch.test.ts`) and a property test over random ops, undo and redo. UI wiring is out of scope here. `ABI_VERSION` is not bumped: the change is additive.

## Test plan (`crates/timeline/src/tests.rs`)
Property tests (proptest, seeded op generator that resolves against the live project, ~76% of ops apply and all 7 kinds succeed): (1) every op: Ok keeps `validate()` true and `apply(inverse)` restores exactly, redo reproduces; Err changes nothing. (2) random op/undo/redo sequences: each undo returns to the recorded earlier state, `replay(journal) == state`, undo-all == base, redo-all == final. Unit tests: every validation rule, locked tracks, split/trim source maths, inexact speed, batch rollback, drag coalescing, redo clearing and the step limit, torn journal, JSON API. Perf test at 5k clips.
**E2 gate (M2-011)**: the generator covers every op (34 kinds: clip edits, tracks, ripple/roll/slip/slide, transform and keyframes, links, media bin, format and canvas, markers and range), and both properties also check, after every op, that clips never overlap on a track, every clip's media exists and a save/reopen round trip gives the same project (links, animated values). `npm run test:e2` runs 10,000 sequences in release mode; the S7 bar is `PROPTEST_CASES=100000 cargo test -p app-timeline --release`. CI runs the default 256 cases (a release 10k step needs a process request). Found and fixed by the gate: undoing `RemoveMedia` put the item at the end of the bin (`AddMedia` now takes an optional `index`, absent = append, so old wire JSON is unchanged), and project JSON lost the last bit of an animated value on reopen (`serde_json` `float_roundtrip`).
