## Time on task (scripted pro on `?sample`, 1440x900)
Keyboard path measured (keys / clicks, every step checked for selection and focus): select clip (1 click), playhead +2 s (`Alt+Shift+Right` x2), split `S`, select the right half `Right`, ripple delete `Shift+Delete`, pick the next clip `Enter`, trim start `[`, nudge `.` and `Shift+.`, marker `M`, undo x3 `Ctrl+Z`: **14 keys + 1 click**, focus stayed on the timeline the whole run, selection and playhead as expected (except #2, fixed). Mouse path for the same edits is one click per toolbar button (Split, Delete, Ripple delete) plus the drags. Steps with no keyboard path: **speed 2x** (Details > Speed tab > preset: 2 clicks), **opacity keyframe** (field + diamond: click, type, click), **Export** (2 clicks). These need a registered command each (palette + remap), which is a feature, not a fix: filed as an `m2-ux` issue (see the PR).

## Motion audit (what the tokens are, what was found)
`--dur-instant` 100 ms (press), `--dur-fast` 150 ms (hover), `--dur-base` 200, `--dur-slow` 250, `--dur-menu` 120, `--dur-dialog` 180, `--dur-toast` 280; easings `--ease-out` / `--ease-in-out`; all 0 s under reduced motion. Grep of every `transition` / `animation` in `apps/web/src`: all on tokens except the two literals in #6 (fixed) and the decorative skeleton pulse (1.4 s loop, no motion under reduced motion). Nothing over 300 ms in UI chrome (longest: toast 280, the commit cue 280). Enter vs exit: menus 120 ms, dialogs 180 ms, toasts 280 ms in; the in and out use the same token, which keeps exits no slower than enters.

## Works, keep it
Snap guides and rotation snapping (round 11), the Details label scrub (kept, now shared with the number), per-field reset, the preview handles at 44 px, the toolbar's "Name (key)" tooltips, all-token motion, the global reduced-motion switch, `no horizontal scroll` at every size (smoke).

## Not verified
- Haptics on a real Android device (no vibration motor here; code path reviewed, the helper is a no-op without `navigator.vibrate`).
- Number scrub with a finger on a phone (the field has `touch-action: pan-y`, a tap focuses it; the sideways drag was tested with a mouse only).
- Light theme of the commit cue (it uses the theme's accent colour, same as the guide line).
- Real-device keyboard repeat rate for the nudge burst (600 ms window).
